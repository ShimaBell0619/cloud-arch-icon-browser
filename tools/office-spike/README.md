# Office interoperability spike harness

This directory contains the reproducible validation harness for GitHub Issue #45. It is deliberately isolated from the production app and production localhost server.

## What this harness answers

The spike validates five distinct questions against real Windows desktop PowerPoint:

1. Can browser Clipboard APIs paste multiple images as **independent PowerPoint shapes** in one paste?
2. Can PowerPoint automation build a hidden temporary slide, copy a `ShapeRange`, close/quit the automation source, and leave a usable multi-shape clipboard payload?
3. Does browser `image/svg+xml` clipboard data paste as a real vector graphic rather than SVG source text or a raster fallback?
4. Can a local/native PowerPoint path preserve SVG as a vector graphic?
5. Can Edge/Chrome drag PNG or SVG directly into desktop PowerPoint reliably?

A flattened bitmap is never a successful result for `Copy all`.

## Safety and scope

- Run only on the Issue #45 target environment: Windows 11, current stable Edge/Chrome, and desktop Microsoft PowerPoint from Microsoft 365.
- All artwork is generated by the harness. No Microsoft Azure icon assets are required or written by these tools.
- The browser harness binds only to `127.0.0.1:41732` and serves three fixed local files with restrictive headers.
- The PowerShell harness uses transient files under the OS temp directory and deletes them deterministically.
- Nothing here is shipped by the npm package. This spike does **not** add a production Office automation endpoint.

## 1. Start the browser harness

From the repository root:

```powershell
node .\tools\office-spike\run-browser-harness.mjs
```

Open `http://127.0.0.1:41732/` in current stable Edge first, then Chrome.

## 2. Browser clipboard checks

For each browser, run the following tests from the page. Immediately after each Copy button, inspect the clipboard with PowerPoint:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\office-spike\powerpoint-interop.ps1 -Mode inspect-clipboard
```

Record the JSON output in `docs/OFFICE_INTEROP_SPIKE.md`.

| Test | Browser action | Required evidence |
| --- | --- | --- |
| A0 | `Copy single PNG` | Baseline: one PowerPoint picture shape |
| A1 | `Copy 3 PNG items` | Success only if one paste yields 3 independent shapes |
| A2 | `Copy HTML with 3 images` | Success only if one paste yields 3 independent shapes |
| C1 | `Copy SVG + PNG` | Record whether PowerPoint pastes `msoGraphic` (28), `msoPicture` (13), or another type |

`inspect-clipboard` creates only a hidden temporary presentation. If PowerPoint was already open, it does not quit the user's PowerPoint process.

## 3. Native PowerPoint multi-shape check

Close all PowerPoint windows first. Then run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\office-spike\powerpoint-interop.ps1 -Mode copy-range
```

The test generates four PNGs (`A`, `B`, duplicate `B`, `C`), inserts them into a hidden 2×2 slide, calls `ShapeRange.Copy()`, closes the source presentation, deletes the PNG files, quits the source PowerPoint automation instance, starts a second hidden PowerPoint instance, and pastes the clipboard for inspection.

The candidate route is viable only when the JSON reports all of the following:

- `pastedShapeCount: 4`
- `independentShapes: true`
- `relativeLayoutPreserved: true`
- `tempImagesDeletedBeforeValidationPaste: true`
- `clipboardSurvivedAutomationQuit: true`
- `copyRangeFeasible: true`

After the automated result succeeds, perform one final human check: open a normal presentation and paste once. Confirm that four objects appear, remain independently selectable/movable, retain the 2×2 layout, and that the automation test did not visibly flash or steal focus in an unacceptable way.

## 4. Native vector check

Close all PowerPoint windows first. Then run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\office-spike\powerpoint-interop.ps1 -Mode vector-range
```

This generates a synthetic SVG, inserts it through PowerPoint `Shapes.AddPicture`, copies it, closes the source, deletes the SVG, quits the source automation instance, then pastes into a second hidden instance.

Record:

- `sourceShapeType`
- `pastedShapeType`
- `vectorGraphicPreserved`
- `clipboardSurvivedAutomationQuit`

`msoGraphic` is type `28`; `msoPicture` is type `13`.

## 5. Direct drag checks

Keep a normal PowerPoint presentation open and drag each harness tile onto a slide in both Edge and Chrome:

1. `PNG file drag`
2. `SVG file drag`
3. `Chromium DownloadURL` — exploratory only

For each, record whether an object is inserted without a manual download, whether it is independently selectable, whether it remains vector/raster as expected, and whether the browser instead downloads/opens a file.

The `DownloadURL` path is non-standard. If it is the only drag route that works, the recommendation should be to **reject/defer direct drag** rather than make it a production dependency.

## Reading the PowerShell result

Every mode writes a single JSON object to stdout and always attempts cleanup in `finally`. `success: true` means the harness executed; individual feasibility is reported under `observations` and still needs to meet the Issue #45 acceptance criteria.

If PowerPoint COM automation is unavailable, busy, denied, or cannot paste the payload, the result contains an actionable `error` and `success: false`.

## Final evidence

Copy the observed browser/PowerPoint versions and results into [`../../docs/OFFICE_INTEROP_SPIKE.md`](../../docs/OFFICE_INTEROP_SPIKE.md). Issue #45 should remain open until the real Windows results are recorded and the decision matrix is finalized.
